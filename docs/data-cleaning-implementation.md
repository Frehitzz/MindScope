# Data Cleaning Implementation

This document outlines the strategies and techniques used in our Python data cleaning pipeline (`data/run_cleaning_pipeline.py`) to prepare the Teen Mental Health Dataset for analysis and storage.

## 1. Handling Missing or Null Values
**File:** `data/cleaning.py`  
**Strategy Used:** Flag and Fill (Median/Mode Imputation)

Our approach ensures no data is arbitrarily dropped while maintaining a record of which values were originally missing:
* **Flagging:** For any column containing missing data, we first create a new binary column (e.g., `age_was_missing`) set to `1` if the data was missing and `0` otherwise. This allows future models to understand that the value was synthetically imputed.
* **Filling Numeric Data:** If the column contains numbers (e.g., `sleep_hours`), missing values are filled using the **median** of that column. The median is chosen over the mean because it is more robust to extreme outliers.
* **Filling Categorical Data:** If the column contains text/categories (e.g., `platform_usage`), missing values are filled using the **mode** (the most frequent value) of that column.

## 2. Normalization / Standardization
**File:** `data/cleaning.py`  
**Method Used:** Min-Max Scaling

We normalize the `daily_social_media_hours` column to put it on a standard mathematical scale between `0.0` and `1.0`. 
* **Implementation:** We calculate the minimum and maximum values of the column. For every row, we subtract the minimum value and divide by the range (`maximum - minimum`).
* **Output:** This creates a brand new column called `daily_social_media_hours_min_max`, preserving the original raw data column while providing the scaled version for machine learning algorithms.

## 3. Filtering Outliers
**File:** `data/cleaning.py`  
**Method Used:** Interquartile Range (IQR)

To prevent extreme, unrealistic values from skewing our analysis, we apply the IQR statistical method to all continuous numeric columns (such as `age`, `stress_level`, etc.):
* **Calculation:** For each column, we calculate the 25th percentile (Q1) and the 75th percentile (Q3). The IQR is the difference between them (`Q3 - Q1`).
* **Boundaries:** We establish a lower bound (`Q1 - 1.5 * IQR`) and an upper bound (`Q3 + 1.5 * IQR`).
* **Action:** Any row containing a value that falls outside these boundaries in any of the checked columns is completely **dropped** from the dataset.

## 4. Cloud Storage Export
**File:** `data/upload_to_supabase.py` & `data/run_cleaning_pipeline.py`  
**Destination:** Supabase (PostgreSQL) via REST API

After the dataframe has been fully cleaned in memory, the pipeline securely exports it to our cloud database:
* **Data Formatting:** The Pandas dataframe is converted into a list of dictionaries (JSON format). Any `NaN` values generated by pandas are safely converted to Python `None` so they are stored as `null` in the PostgreSQL database.
* **Chunking Strategy:** To ensure reliable delivery and avoid hitting API payload limits ("413 Payload Too Large"), the data is sliced into chunks of 200 records at a time.
* **API Upload:** The script uses the Python `requests` library to make authenticated `POST` requests directly to the Supabase REST API, inserting the cleaned data into the `teen_mental_health_cleaned` table.
